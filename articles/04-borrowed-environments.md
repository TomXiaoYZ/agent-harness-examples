# 环境是借的：27 个废弃 worktree，和每份 5 GB 的数据副本

前三篇讲了任务卡、钩子和线程可见性。这一篇讲 Agent 干完活之后留下的东西：worktree、测试容器、数据卷、镜像。没人负责收，它们就一直堆着。2026 年 11 月 10 日我在自己的机器上做了一次盘点，结果如下。

## 盘点

**worktree**

- 某 SaaS 仓库有 27 个 worktree。其中 20 个对应的 PR 早已合并，1 个已关闭，全部干净无改动，每个约 105 MB。
- 某数据平台仓库有 18 个。其中 7 个有未提交改动，有一个已经 20 天没动过；还有 2 个目录已经不存在，但 git 元数据还在。
- 某量化研究仓库有 14 个，**每个 4.8–5.2 GB**。原因是 4 GB 的数据和 800 多 MB 的归档被 git 跟踪：21462 个跟踪文件里有 19106 个在这两个目录。每开一个 worktree，就完整复制一遍 5 GB。
- worktree 的位置一共有 6 种：Claude Code 的、Codex 的、我派发脚本的、`/tmp` 的、手工建的……没有任何一个脚本能列全，更没有脚本敢删。

**Docker**

- 容器 32 个，2 个在运行。30 个已退出的里，有不少是任务里手动起的测试数据库，没有标签，也没有 compose 项目名。
- 卷 45 个，其中 27 个无人使用，合计 8.7 GB 可回收。真正占空间的两个大卷（76 GB 和 37 GB）是项目数据，不是垃圾。

结论是：Docker 这边是**习惯问题**，可回收的体积其实不大；worktree 这边是**数量和注意力问题**。另外，数据放在代码树里，是磁盘问题的真正来源。

## 根因：借出去的东西，没有归还条件

创建 worktree 的机制有四种（Claude Code、Codex App、我的派发脚本、手工），没有一种在“任务完成”时有明确的回收动作：

- Claude Code 只在交互式会话退出时提示删除；命名会话、脚本跑的会话、桌面 App 的会话都不触发。
- “已合并”没法机械判定。PR 的目标分支是 `sit`、`feat/v3-x` 这类分支，按 `main` 算祖先，全都显示“领先 900 多个提交”。不查 PR 状态就不敢删，于是谁都不删。
- 测试容器没有身份，任务结束后就成了孤儿。

## 规则：创建时就写好归还条件

我写进全局约定的只有一句：**Agent 创建的 worktree、容器、卷、镜像都是借的，创建时就要定好归还条件。** 比如“卡被接受并合入”“PR merged 或 closed”“会话归档”。归还属于这条任务的完成定义，不另开一个清理任务。PR 合并不等于收口。

然后用脚本和钩子强制执行，不靠文字：

1. **只用一个入口建任务 worktree。** 位置固定在 `<repo>/.worktrees/<task>`，同时登记到一份环境账本。每个仓库超过 8 个就拒绝新建，提示先收口。另有一个全局钩子拦截裸的 `git worktree add`，把人指回这个入口。
2. **稀疏检出。** 仓库根目录放一个 `.worktree-sparse` 文件，列出不需要检出的数据目录。量化研究仓库排除两个数据目录后，一个 worktree 预计从 5 GB 降到 350 MB 左右（在临时仓库里验证过被排除的数据不会落地）。
3. **容器必须带身份。** 用 `docker compose -p <task>` 或 `--label agent.task=<task>` 起容器，任务完成前 `down -v`。Codex 回合结束的自检钩子会查有没有带这个标签的残留，有就退回。
4. **巡检脚本先出报告，再动手。** 按 PR 状态判断是否完成，不按祖先判断。处理方式分三档：
   - 干净且 PR 已合并的，直接收回；
   - 有改动的，先打快照放进废纸篓，再删；
   - 数据卷永远不自动删，因为里面可能是不可再生的数据。

## 效果和还没解决的

当天执行完安全类清理和快照删除，全机 worktree 从 92 个降到 39 个，废纸篓里的快照一共 11 MB。三天后体检，剩 29 个。

但它不是零，规则也没有自动生效：

- 有 7 个 worktree 被人直接 `git worktree remove` 删掉，没走归还入口，账本和现实对不上。后来改成巡检时先按“目录已不存在”补记归还。
- “卡已验收但 worktree 还在”的提醒，因为脚本读错了文件，一直没触发过，体检时才发现。修好后，当天的体检里就列出一张已验收、worktree 却还没归还的卡。

规则只能让问题暴露出来，真正收尾仍然要有人去做，而且检查脚本本身也要被检查。

## 可以拿走的东西

- 一句规则：借出去的环境，在创建时就写好归还条件。
- 三个机制：一个统一入口，并设数量上限；稀疏检出，排除数据目录；容器带任务标签，配合回合末检查。
- 一个底线：数据卷不自动删；清理先进废纸篓，并留一份清单。

这是这个系列的第 4 篇。如果你也在用 Claude Code、Codex 或其他 Agent 组合跑真实项目，欢迎在评论里讲讲你遇到的坑。

## 数字说明

- 盘点日期：2026-11-10，单台 macOS 开发机，Docker 跑在 OrbStack 上。
- 105 MB、4.8–5.2 GB：当日每个 worktree 的磁盘占用。
- 350 MB：方案里的估算值；实际验证在临时仓库上做，确认被排除的目录不检出。
- 92 → 39：同日 `--apply` 安全类清理加快照删除后的全机 worktree 数；29：2026-11-13 体检时的数。
