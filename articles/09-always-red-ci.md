# CI 连红 6 天，19 个 PR 照样合入：45 项失败一项没变过，红灯就成了背景色

结论先说：**一条永远是红的 CI，和没有 CI 一样。** 我管 Agent 工作流的那个仓库，CI 从第一次运行起就是红的，连续红了 6 天、24 次，这期间合入了 19 个 PR。每次都是同样的 45 项失败，其中 40 项根本不是代码问题，而是仓库导入时丢了文件的可执行位和符号链接。修好只花了一个提交，之后 15 次运行全部通过。

背景：这个仓库放的是我的钩子、派发脚本、技能和全局规则。Claude Code 和 Codex 每个会话都从它加载规则，所以它坏了，所有项目都受影响。前几篇讲的守卫、看板、提醒钩子，都住在这里。

## 发生了什么

11 月 14 日，仓库第一次在 GitHub 上跑 CI（一个叫 Verify 的工作流，每个 PR 跑一遍 pytest 和两个检查脚本）。结果：

- 第一次：45 项失败，91 项通过；
- 到 11 月 20 日最后一次红灯：45 项失败，127 项通过。

六天里新加了 36 项测试，全都通过；失败数一项没变。期间一共跑了 24 次，全部失败，涉及 20 个分支；合入了 19 个 PR，包括第 2 篇讲的审计误报修复和第 8 篇讲的长会话提示。

失败日志里 40 行是同一个错：`PermissionError: [Errno 13] Permission denied`。测试直接执行脚本，脚本却没有可执行位。

## 为什么六天没人管

不是没人看见。11 月 15 日晚上的盘点文档里已经写清楚了原因，还标了“可以直接开工”：

- 带 `#!` 的脚本在 git 里全是 `100644`，没有可执行位；
- 两个文件本来是符号链接，导入时被压平成了普通文件，内容只有一行相对路径，执行时报 `Exec format error`；
- 在临时副本里实验：补上可执行位，45 项降到 20 项；再把两个链接改回来，降到 7 项；其中 2 项是副本没提交记录造成的，真正剩下 5 项。
- 这 5 项是从上游模板继承来的断言，检查的是别人环境里的条款和文件，在我这里本来就不该成立。

文档写完之后，又红了 19 次，又合入了 15 个 PR，才有人去修。

我的判断是：**红灯每次都一样，就不再是信号了。** 每个 PR 的 CI 都是红的，红本身说明不了任何事，合入时也就没人去比这次是 45 个还是 46 个。新加的测试如果坏了，会被淹没在旧的红灯里。

还有一点：这是私有仓库，免费账号没有分支保护，“检查不通过不许合”这条规则平台层面设不了。我今天用 API 查，返回 403。所以合不合，全看合入的那一方看不看。

## 修法：一个提交

11 月 20 日的修复只做了三件事：

1. **补可执行位。** git 记录了 34 个文件从 `100644` 改成 `100755`。
2. **两个伪链接改回真正的符号链接**（git 里模式是 `120000`）。
3. **继承来的断言换成我自己现在的约束**，不是删掉了事：
   - 全局规则文件必须保留“必须保留的边界”那六条（比如不自行推送到 main、凭据只放系统钥匙串）；
   - README 里的本地链接必须都能打开；
   - 全局规则文件不超过 10 KB。

之后 16 次运行：15 次通过，1 次因为同一分支有新推送被自动取消。最新一次是 190 项全部通过。

## 规则落在哪

- **Verify 工作流**：每个 PR 跑 pytest、技能包检查、仓库上下文检查。测试是直接执行脚本的，可执行位再丢一次，CI 立刻变红。现在 CI 是绿的，红了就是新问题。
- **`tests/test_agent_context.py`**：六条边界一条不能少。这是我最怕在“精简规则”时被顺手删掉的东西，现在删了测试就挂。
- **`tests/test_readme_contract.py`**：README 的本地链接都要能解析。

## 两件没解决的事

- **合入门禁还是靠人。** 平台设不了必过检查，我也还没在合入命令里加一步“检查没过就停”。现在能做的只是：CI 是绿的，红灯终于有意义了。
- **10 KB 上限是放宽出来的。** 上游的上限是 4000 字节，我的规则文件 11 月 15 日是 7314 字节，今天是 9407 字节。修复时把上限改成了 10 KB，注释里写着“再加规则就得先删”。瘦身这件事没做，只是把天花板定在了现状上面一点。

## 可以拿走的做法

1. **导入或迁移仓库后，先查文件模式。** 下面这段只读 git 对象，不碰工作区。在修复前的那个提交上跑，正好报出 34 个缺可执行位和 2 个压平的链接；在现在的 main 上跑，没有输出。

```sh
ref=${1:-HEAD}
git ls-tree -r "$ref" | while read -r mode type sha path; do
  [ "$mode" = 100644 ] || continue
  head=$(git cat-file -p "$sha" | head -c 64)
  case "$head" in
    '#!'*) echo "缺可执行位: $path" ;;
    ../*) [ "$(git cat-file -p "$sha" | wc -l)" -eq 0 ] && echo "疑似压平的符号链接: $path" ;;
  esac
done
```

2. **CI 第一次跑红，先把它修绿，再做别的。** 一直红的 CI 不是“有点问题的 CI”，是没有 CI。判断标准很简单：连续几次失败数完全一样，就说明没人在读它。
3. **继承来的断言，换成自己的约束，不要直接删。** 删掉测试会变绿，但也什么都不守了。想清楚“我最怕丢的是什么”，写成新断言，在注释里写原因。
4. **平台设不了必过检查，就把检查写进合入那一步。** 这一条我自己还没做，先列在这里。

这是系列第 9 篇。前几篇反复说“规则要放在 Agent 绕不开的地方”。这一篇是反面：检查放在了绕不开的地方，但它一直是红的，大家就学会了绕过它。
