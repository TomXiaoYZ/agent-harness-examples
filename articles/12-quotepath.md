# git 把中文文件名转成八进制：补齐脚本报“仍不合规 0”，其实跳过了 34 份文档

结论先说：**脚本说“剩余 0”，只代表它看得见的范围里是 0。** 11 月 17 日凌晨，我让 Agent 在 9 个个人仓库里批量给文档补元数据，每个仓库的补齐脚本都报“仍不合规 0”。跑完换一种方式复核，4 个仓库里还有 34 份不合规，全是带中文的文件名。原因是 git 默认会把非 ASCII 的路径转成八进制、再整体加上双引号，脚本按 `.md` 结尾过滤，这些文件就被悄悄丢掉了，没有任何报错。同一个问题也让提交前的检查门禁对中文文件名完全失明。修法是一个提交，3 个文件、加 13 行删 2 行。

背景：我给所有仓库的 `docs/` 定了一套文档规范，每份文档开头要有一段元数据（类型、作者、日期、来源等）。配套两个脚本：一个检查脚本，提交前用 `--changed` 只查本分支改过的文档，Agent 的全局规则要求每次改文档都跑；一个补齐脚本，给老文档批量补元数据。两个脚本都靠 git 列文件。

## 发生了什么

那天凌晨的顺序是这样的：

- 02:10（美东），检查脚本和规范合入。
- 02:27，补齐脚本在 9 个仓库各跑一遍。每个仓库都打印“已补 N 个文档，仍不合规 0”，合计补了 1,019 份，正文逐份比对过，没有改动。
- 同一轮里，Agent 又用检查脚本的全量模式把每个仓库查了一遍。4 个仓库不对：1 份、23 份、9 份、1 份，合计 34 份“缺少元数据”。列出来的文件名，每一个都带中文。
- 10 秒后 Agent 给出判断：git 默认把中文文件名加引号转义，补齐脚本跳过了它们，检查脚本的 `--changed` 也有同样的问题。
- 02:28，修复提交合入。重跑后这 34 份补齐，9 个仓库全量检查都是 0 个不合规。

从看到 34 到修复合入，不到 2 分钟。这次运气好，是因为两个模式列文件的方式不一样，结果对不上，才被看见。

## 为什么会这样

git 有个配置叫 `core.quotepath`，默认开着。开着的时候，路径里只要有非 ASCII 字节，`git ls-files`、`git diff --name-only`、`git status --porcelain` 的输出就会变成这样：

```text
docs/plain.md
"docs/\344\270\255\346\226\207\346\226\207\346\241\243.md"
```

第二行是 `docs/中文文档.md`：每个字节写成反斜杠加三位八进制，整行包在双引号里。

三层原因叠在一起：

**第一层：过滤条件把它当成了别的文件。** 补齐脚本先 `git ls-files docs`，再筛 `f.endswith(".md")`。转义后的行以双引号结尾，筛掉了。检查脚本的 `--changed` 也是 `git diff --name-only` 加同样的后缀过滤。没有报错，没有警告，那一行就像不存在。

**第二层：“剩余”是在自己看见的范围里算的。** 补齐脚本的“仍不合规 0”是对它列出来的那些文件说的，这句话本身没错。错在读的人（包括 Agent）把它理解成“这个仓库里 0”。

**第三层：门禁漏了，但是绿的。** `--changed` 是 Agent 每次改文档前都要跑的检查。如果某个分支新增一份中文名、没有元数据的文档，它列不出来，返回 0，看起来一切合规。检查脚本从合入到修复只有 18 分钟，所以这一层没有造成实际漏检。但如果没有那次全量复核，这个洞会一直开着，而且永远是绿的。

为什么全量模式没中招？它不问 git，直接用 Python 的 `rglob("*.md")` 扫文件系统。两条路径列出来的文件数对不上，问题才露出来。

## 修法：一个提交

1. **两个脚本的 git 封装函数各加一个参数**：`["git", "-C", repo, "-c", "core.quotepath=off", *args]`。所有 git 调用都经过这个封装，改一处就全改了。
2. **加一条测试**：在临时目录建一个 git 仓库，先提交一份合规文档作为基线，再写入 `docs/kb/中文文档.md`，内容只有一行标题、没有元数据，断言 `--changed` 返回 1。修复前这条测试会返回 0。

修完这个测试文件 9 条全过。

为什么不直接在本机 `git config --global core.quotepath off`？因为全局配置只在我这台机器上。CI、新开的容器、Codex 的沙箱，都是默认值。我本机其实也没设（查了一下，全局配置里没有这一项）。把参数写进脚本里，脚本在哪跑都一样。

## 规则落在哪

- **两个脚本的 git 封装函数**：路径输出一律不转义。
- **测试 `test_changed_handles_non_ascii_names`**：谁把这个参数删了，CI 就挂。

## 没解决的事

- **同一个仓库里还有一个脚本有同样的问题。** 写这篇之前，我把那个仓库里调用 `ls-files`、`--name-only`、`--porcelain` 的脚本都翻了一遍，还有 2 个没加这个参数。一个只判断 `status --porcelain` 的输出是不是空的，不受影响。另一个是归还任务工作树时做快照的那段：从 `status --porcelain` 里取未跟踪文件打包，然后强制删除工作树。我在临时仓库里复现过，中文名的未跟踪文件会被判成“不存在”，不进快照包，然后跟着工作树一起删掉。有没有真的因此丢过文件，我不知道。这个还没修。
- **用的是关转义，不是 `-z`。** `-z` 用 NUL 分隔，空格、换行、引号这些都不怕，是更彻底的做法。这次只修了已经咬到人的那一种。

## 可以拿走的做法

1. **脚本要解析 git 输出的路径，就在封装里统一关掉转义。** `-c core.quotepath=off` 写在每次调用里，或者改用 `-z`。不要指望运行环境的全局配置。
2. **测试夹具里放一个中文文件名。** 一条测试就够，它守的是“有人把参数删了”。
3. **数一下你会丢多少。** 下面这段比较默认设置和关闭转义时 git 列出的 `.md` 数，差值就是会被后缀过滤丢掉的文件。用 `sh` 跑。我今天在那 9 个仓库的 `docs/` 上各跑了一遍：4 个仓库有差值，合计 57 份。

```sh
#!/bin/sh
# 用法：quoted_count.sh [路径]；比较默认设置和关闭转义时 git 列出的 .md 数，差值就是会被按后缀过滤掉的文件
p=${1:-.}
a=$(git ls-files -- "$p" | grep -c '\.md$')
b=$(git -c core.quotepath=off ls-files -- "$p" | grep -c '\.md$')
echo "default $a  quotepath=off $b  lost $((b - a))"
```

4. **“剩余 0”要换一条路径复核。** 让统计“剩余”的东西和做事的东西用不同的方式列文件，比如一个走 git，一个走文件系统。两边数字一致才算完。

这是系列第 12 篇。前面几篇讲的多是 Agent 绕不绕得开规则，这一篇是规则自己看不见东西：检查本身是对的，只是有一类文件从来没被送到它面前。检查报绿之前，先确认它看到了全部。
